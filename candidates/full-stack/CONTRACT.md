# Shared candidate contract v1

Independent candidate package org.momhealth.gateway.candidate. Baseline remains untouched. Backend and Android wire contract agreed before delegation:
POST /v1/batches JSON {schema_version:1, batch_id:UUID-string, samples:[...]}, maximum100 samples.
Each sample exact keys: sample_id (UUID string), device_id (opaque identifier, not direct BLE address), session_id (UUID string), model (V1|V4|V8), source (live|history), received_at (timezone-aware ISO8601), measured_at (ISO8601 or null; do not invent device time), heart_rate_bpm (integer20..250 or null), missing_reason (null or no_result|unsupported|not_requested|unknown), synthetic (boolean).
No BP/glucose/clinical claims. No unimplemented metric values. Receipt time != device sample time. Server returns {batch_id, accepted_ids:[...], duplicate_ids:[...], rejected:[{sample_id,reason}]} after transaction commit. ID collision with differing content rejects that item; duplicates with identical content idempotent. All rejected entries remain pending on client. Duplicate-ID-within-batch requests reject before mutation. Validate request size, count, identifier/date types.
GET /v1/health, GET /v1/samples?device_id=...&limit=...&cursor=...; bounded pagination, nullable HR/provenance. Local-only synthetic testing by default; real-data ingest must default disabled through explicit server configuration. No authentication tokens generated or ongoing credentials configured. Bind runnable local test server127.0.0.1 only.
App storage opt-in and explicit upload only. No background jobs/autoreconnect. New features must not auto activate or alter baseline BLE. Android native SQLite, HttpURLConnection, org.json available. Candidate transport network code can be written/tested locally; no real health transmissions. Backend SQLite tests + PostgreSQL adapter/schema; PostgreSQL runtime validation blocker tracked separately.
