## Specification gaps versus validation gaps

V4 command UUIDs, checksum construction, battery/firmware, manual HR command/response and activity prefix are in extracted source. The audit therefore adds the adapter. Hardware validation is still needed for actual notification lengths, manual/reporting behavior and physical Stop behavior; that is not represented as absent command documentation.

All three SDKs document static/dynamic HR history commands and record prefixes. Demo flow provides start/continue and a callback-count pagination heuristic. The inactive planner models those facts, including bounded timeout, write acknowledgment and isolated identity, without claiming a successful live transfer. The SDK's use of arbitrary short packets or trailing FF as completion does not unambiguously distinguish truncation from a valid terminator. Record bytes 1–2, stable record identity, exact terminal framing for each firmware, dynamic sample spacing and timezone/DST interpretation are not established by the reviewed evidence. See `HISTORY_COMPONENT.md` for exact paths/lines and which assumptions are intentionally not made. No history deletion or clock/configuration write is generated.
