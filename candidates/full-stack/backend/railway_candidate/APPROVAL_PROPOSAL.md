# Synthetic Railway test: decision and limits

This is a proposal only. It does not authorize creation or operation. No resource, credential, domain or data transfer has been created.

Target: a dedicated new Mom Health synthetic-test project in the existing personal Railway workspace `cyberike's Projects`, rather than modifying either existing project. One service, one replica and one private persistent test volume up to 0.5 GB, with a Railway-provided HTTPS domain; use fictional records only. Runtime service CPU/memory limits must be set only after inspecting the account plan and confirming platform support. Start no production or real-data mode. Disable or stop the test after an explicitly agreed test window; exact duration and retention/deletion of synthetic test records need agreement.

Access: one caregiver username and high-entropy password for the protected dashboard and read routes; an independent high-entropy write-only phone/API token stored in Railway environment variables. Values must be generated through an approved secure channel and not placed in source, URLs, logs, or chat. Both are persistent credentials and require explicit authorization. Browser Basic authentication caches credentials and lacks independent logout/revocation. Rotation and revocation procedures require verification.

Cost: the existing workspace plan, current consumption, available credits, current limits and marginal charges are unknown. Railway publishes a $5/month Hobby minimum including $5 usage, with additional resource usage above that amount. A user-specified maximum additional spend and deployment duration are required before provisioning. Do not set a workspace-wide usage hard limit without separate explicit approval: it can stop all existing workloads in that workspace. Source: https://railway.com/pricing and https://docs.railway.com/pricing/cost-control.

Safety prerequisites before making an internet endpoint reachable: independently verify exact Railway ingress transport peers and exclusive origin/TLS path; configure and test ingress abuse prevention; verify mount ownership/mode, filesystem isolation, durability and backups. The local global per-role limiter is a process-local backstop and can deny legitimate users, reset on restart, or be bypassed across replicas. Actual peer ranges, storage policy and Railway topology are not established by unit tests. Public access and security configuration changes require approval.

The last attempted local Chrome visual check failed with Windows IPC `Access denied` (crashpad/Mojo); no screenshot was produced. No permission denial was bypassed. A supported browser session with authorized Windows IPC access or a separately approved execution route is needed for real browser Basic-auth, keyboard and rendering QA. Do not use sandbox-disabling flags. Android uploads real watch observations marked synthetic=false, so the synthetic-only gateway rejects them. Test transport using a fictional fixture client; do not upload watch readings.

Only after the above prerequisites are concretely resolved and a resource/cost proposal is approved should a synthetic deployment be attempted. Real-health-data activation, real phone uploads, device installation and unattended operation require separate explicit decisions and acceptance.
